# Git 팀 협업 워크플로우

## 개요

이 실습에서는 2-3명이 팀을 이루어 Git의 협업 워크플로우를 경험합니다.

**배울 내용:**
- Feature Branch 전략
- Pull Request (PR) 생성
- 코드 리뷰
- Merge

---

## 역할 분담

### 3인 팀

| 역할 | 담당 파일 | 구현 함수 | 브랜치명 |
|------|----------|----------|---------|
| **팀원 A** | `src/calculator.py` | add, subtract, multiply, divide | `feature/calculator` |
| **팀원 B** | `src/statistics.py` | mean, median, mode, variance | `feature/statistics` |
| **팀원 C** | `src/utils.py` | validate_numbers, round_result, format_output | `feature/utils` |

### 2인 팀

| 역할 | 담당 파일 | 브랜치명 |
|------|----------|---------|
| **팀원 A** | `src/calculator.py` + `src/utils.py` | `feature/calculator`, `feature/utils` |
| **팀원 B** | `src/statistics.py` | `feature/statistics` |

## Phase 1: 환경 설정 (15분)

### Step 1: 팀장 - 저장소 Fork

1. 강사가 공유한 GitHub 저장소로 이동
2. 우측 상단 **Fork** 버튼 클릭
3. 자신의 GitHub 계정으로 Fork

### Step 2: 팀장 - 팀원 초대

1. Fork한 저장소 → **Settings** → **Collaborators**
2. **Add people** 클릭
3. 팀원들의 GitHub ID 입력하여 초대
4. 팀원들은 이메일 또는 GitHub 알림에서 초대 수락

### Step 3: 모든 팀원 - Clone

```bash
# VSCode에서 Ctrl+Shift+P → "Git: Clone" 또는 터미널에서:
git clone <팀장-Fork-저장소-URL>
cd Day02_Git-Team-Collaboration
```

### Step 4: 환경 설정

```bash
# 가상환경 생성 (권장)
python -m venv venv

# 가상환경 활성화
# Windows:
venv\Scripts\activate
# Mac/Linux:
source venv/bin/activate

# 의존성 설치
pip install -r requirements.txt
```

### Step 5: pytest 동작 확인

```bash
# 테스트 목록 확인 (아직 모두 실패할 것임)
pytest --collect-only

# 테스트 실행 (실패 예상)
pytest
```

예상 결과:
```
FAILED tests/test_calculator.py::TestAdd::test_positive_numbers
FAILED tests/test_calculator.py::TestAdd::test_negative_numbers
... (모든 테스트 FAILED)
```

## Phase 2: Feature Branch 작업 (30분)

### 각 팀원이 해야 할 일

#### 1. 브랜치 생성

```bash
# 팀원 A
git checkout -b feature/calculator

# 팀원 B
git checkout -b feature/statistics

# 팀원 C
git checkout -b feature/utils
```

#### 2. 함수 구현

각자 담당 파일을 열어 TODO 부분을 구현합니다.

**예시: 팀원 A - calculator.py의 add 함수**

```python
# 변경 전
def add(a: float, b: float) -> float:
    # TODO: 구현하세요
    pass

# 변경 후
def add(a: float, b: float) -> float:
    return a + b
```

#### 3. 테스트 실행

구현 후 반드시 테스트를 실행하여 확인합니다.

```bash
# 팀원 A - calculator 테스트만 실행
pytest tests/test_calculator.py -v

# 팀원 B - statistics 테스트만 실행
pytest tests/test_statistics.py -v

# 팀원 C - utils 테스트만 실행
pytest tests/test_utils.py -v
```

#### 4. 변경사항 확인 및 커밋

```bash
# 변경사항 확인
git status
git diff

# 스테이징
git add src/calculator.py  # 또는 담당 파일

# 커밋
git commit -m "feat: 사칙연산 함수 구현

- add: 두 수의 합 반환
- subtract: 두 수의 차 반환
- multiply: 두 수의 곱 반환
- divide: 나눗셈 (0으로 나누기 예외 처리)"
```

**커밋 메시지 형식:**
- `feat:` 새 기능
- `fix:` 버그 수정
- `docs:` 문서 수정
- `refactor:` 리팩토링

#### 5. 원격 저장소에 Push

```bash
# 팀원 A
git push -u origin feature/calculator

# 팀원 B
git push -u origin feature/statistics

# 팀원 C
git push -u origin feature/utils
```

## Phase 3: Pull Request 생성 (10분)

### Step 1: GitHub에서 PR 생성

1. GitHub 저장소 페이지로 이동
2. **Pull requests** 탭 클릭
3. **New pull request** 버튼 클릭
4. `base: main` ← `compare: feature/calculator` 선택
5. **Create pull request** 클릭

### Step 2: PR 내용 작성

```markdown
## 구현 내용

- add: 두 수의 합 반환
- subtract: 두 수의 차 반환
- multiply: 두 수의 곱 반환
- divide: 나눗셈 구현 (0으로 나누기 예외 처리 포함)

## 테스트 결과

모든 테스트 통과 (17/17)

## 리뷰 요청사항

- divide 함수의 예외 처리가 적절한지 확인 부탁드립니다.
```

### Step 3: 리뷰어 지정

- **Reviewers** 옆의 톱니바퀴 클릭
- 다른 팀원 선택

---

## Phase 4: 코드 리뷰 (15분)

### 리뷰어가 할 일

1. **Files changed** 탭에서 코드 확인
2. 코드 라인에 마우스를 올리면 **+** 버튼 표시
3. **+** 클릭하여 코멘트 작성

### 리뷰 체크리스트

- [ ] 함수가 예상대로 동작하는가?
- [ ] 엣지 케이스가 처리되었는가? (빈 리스트, 0으로 나누기 등)
- [ ] 코드가 읽기 쉬운가?
- [ ] 테스트가 모두 통과하는가?

### 코멘트 예시

```
👍 깔끔하게 구현되었네요!

💡 제안: divide 함수에서 b == 0 체크를 명시적으로 하면 더 좋을 것 같아요.

❓ 질문: multiply에서 음수 처리는 어떻게 되나요?
```

### 리뷰 제출

1. **Review changes** 버튼 클릭
2. 옵션 선택:
   - **Comment**: 단순 코멘트
   - **Approve**: 승인 ✅
   - **Request changes**: 수정 요청 ❌
3. **Submit review** 클릭

---

## Phase 5: Merge (5분)

### 조건

- 최소 1명의 Approve 필요 (팀 규칙에 따라)
- 모든 테스트 통과 (CI 연동 시)

### Merge 방법

1. PR 페이지 하단의 **Merge pull request** 클릭
2. **Confirm merge** 클릭
3. (선택) **Delete branch** 클릭하여 브랜치 정리

### 다른 팀원: main 업데이트

```bash
# main 브랜치로 이동
git checkout main

# 원격 변경사항 가져오기
git pull origin main
```

## 자주 발생하는 문제

### 1. Push 권한 없음

```
remote: Permission to xxx denied to yyy
```

**해결**: 팀장이 Settings → Collaborators에서 팀원을 추가했는지 확인

### 2. 최신 main이 아님

```
! [rejected] feature/xxx -> feature/xxx (non-fast-forward)
```

**해결**:
```bash
git checkout main
git pull origin main
git checkout feature/xxx
git rebase main
# 또는
git merge main
```

### 3. 테스트 실패

```
ModuleNotFoundError: No module named 'src'
```

**해결**: 프로젝트 루트 디렉토리에서 pytest 실행
